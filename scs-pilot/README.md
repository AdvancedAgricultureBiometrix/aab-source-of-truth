# SCS pilot — vertical proof (scaffold)

Project structure for the Supply Chain Sovereignty pilot. **No capability logic is implemented.** The one piece with real content is the SCS-CAP-01 database table, `packages/db/schema/cap-01.sql`, which implements the `ScsRegulatoryFramework` record from its canonical contract.

| Path | What it is |
|---|---|
| `docker-compose.yml` | Local stack: PostgreSQL 17, MinIO (S3-compatible, not yet used), and an API placeholder |
| `.env.example` | Every environment variable, with placeholder values only |
| `packages/api` | Node.js 24 + TypeScript HTTP server. It exposes `GET /health` only |
| `packages/api/src/capabilities/cap-NN` | One placeholder per capability, linking to its canonical contract |
| `packages/db/schema/cap-01.sql` | Current-state definition of the CAP-01 table |
| `packages/db/migrations/001_initial.sql` | Applied history. Creates the CAP-01 table and nothing else |

## Run locally

```bash
cp .env.example .env
docker compose up -d
curl http://127.0.0.1:3000/health
```

## Database standard

Every governed record gets a `uuid` primary key, generated by the database by default. The contracts say `string` for identifiers only because TypeScript has no uuid type. Every SCS table follows this, starting with CAP-01.
