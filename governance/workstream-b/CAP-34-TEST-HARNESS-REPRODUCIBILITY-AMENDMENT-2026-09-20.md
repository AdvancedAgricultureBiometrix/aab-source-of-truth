# CAP-34 Test Harness Reproducibility Amendment

**PR:** `AdvancedAgricultureBiometrix/aab-source-of-truth#16`
**Reviewed antecedent head:** `3c3c35d498284a4dfea15d9a7947de0139ee3934`
**Amendment commits:** `ea26721` (harness fix), `f545294` (evidence freeze)
**Amendment date:** 2026-09-20
**Classification:** Reproducibility-defect correction. No capability, manifest, roster, receipt-contract, or evidence-*content* change. No expansion of PR #16 authority.

## Defect

At the reviewed antecedent head (`3c3c35d`), the three CAP-34 behavioural test harnesses could not execute against the committed repository state:

- `simulation/cap34/capability-fidelity-manifest.behavioural-test.js`
- `simulation/cap34/cap34-canonical-end-to-end.behavioural-test.js`
- `simulation/cap34/cap34-pathway-preview.behavioural-test.js`

Each referenced filenames that were never committed to the repository — a `PR16-`-prefixed alias convention and a differently-named/cased validator, roster, registry and snapshot-registry scheme — instead of the files actually present under `simulation/cap34/`. Running any of the three from a clean checkout failed immediately with `ENOENT`, before a single fixture executed. This condition existed from the harnesses' first commit (`b35c398`) onward; it was not introduced by a later change.

The PR description's claim of "64/64 fixtures passing" and independent reproducibility was therefore **not reproducible from the committed branch** at the antecedent head, notwithstanding the frozen proof records present in `governance/workstream-b/` (see **Superseded evidence** below).

## How this was caught

This was not caught during authoring or in the original review that produced the antecedent head. It was found by independent verification performed against a fresh `git clone` of the PR branch — deliberately excluding the working tree the harnesses were authored in — as a direct check of the PR's own reproducibility claim, rather than by trusting that claim.

## Fix scope

Commits `ea26721` and `f545294` are the full and exact fix. Both are confined to:

- `simulation/cap34/capability-fidelity-manifest.behavioural-test.js`
- `simulation/cap34/cap34-canonical-end-to-end.behavioural-test.js`
- `simulation/cap34/cap34-pathway-preview.behavioural-test.js`
- `simulation/cap34/README.md`
- the three frozen proof records under `governance/workstream-b/` (see below)

No manifest, roster, registry, snapshot, validator, simulation or disclosure-receipt logic file was modified. The hardcoded git-blob SHAs the canonical end-to-end harness binds against were already byte-identical to the real files at `governance/workstream-b/` and `simulation/cap34/` — confirming the uncommitted `PR16-*` alias files were never actually necessary, only the harness's read paths were wrong.

This project has a standing rule against silent replacement of qualification evidence. The following proof records were generated against the broken harnesses at the antecedent head and carried claims that were not independently reproducible. They have been superseded, not silently overwritten — the broken-provenance blobs remain permanently retrievable from Git history at the SHAs below, and this record exists specifically so that history does not read as clean when it was not.

The antecedent blobs were themselves generated by running the broken harnesses in an uncommitted working tree that happened to still contain the missing `PR16-*`/differently-named alias files locally — they were never reproducible by a third party from the committed branch alone.
